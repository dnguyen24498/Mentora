# Source of Truth and Change Policy

**Status:** Reconciled implementation specification  
**Baseline:** Mentora Architecture Baseline 1.0  
**Purpose:** Prevent architecture drift across all files.

## Dependencies

- None

## Normative Language

**MUST**, **MUST NOT**, **SHOULD**, **SHOULD NOT**, and **MAY** are requirements. Technology choices explicitly marked `PROPOSED` are not binding until accepted.

---

## Precedence

1. Security, privacy, tenant-isolation, and classroom consistency invariants.
2. `governance/DECISION_LEDGER.yaml` entries with status `LOCKED`.
3. Canonical architecture files under `docs/architecture/`.
4. Machine-readable contracts under `contracts/`.
5. State machines and sequence specifications.
6. Data/provider/security/operations/test specifications.
7. Proposed ADRs and examples.

## Change policy

A change to a LOCKED decision requires a superseding decision record, impact analysis, affected-file list, migration plan, rollback plan, and updated traceability. Detailed files MUST NOT introduce a different component name, owner, versioning rule, or technology choice.

## Canonical rule

`ARCHITECTURE_FULL.md` is generated by concatenating numbered canonical files. The numbered files are edited; the generated file is not edited independently.

## Technology neutrality

The canonical architecture requires capabilities such as an ordered per-class command mechanism and an SFU. It does not lock Kafka, LiveKit, Temporal, OpenSearch, or a specific cloud unless an ADR is explicitly accepted. All technology ADRs in this package are `PROPOSED`.
