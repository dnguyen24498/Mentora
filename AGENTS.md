# AGENTS.md

## What this repo is

Two layers in one repo:

- A large **reconciled engineering specification** (`docs/`, `governance/`, `contracts/`, `config/`, `tasks/`) that is the source of truth for the AI Teacher Platform (Mentora) — a real-time AI teaching/classroom system.
- A small **implemented backend** (`backend/`) that follows that spec, plus a minimal **frontend** (`frontend/`) upload UI. `workers/` and `infra/` are still skeletons (`.gitkeep` only).

Target V1 shape is a **modular monolith**; split into microservices only when scaling demands it.

## Sources of truth and precedence

- `SOURCE_OF_TRUTH.md` defines precedence: security / tenant-isolation / classroom invariants > `LOCKED` decisions in `governance/DECISION_LEDGER.yaml` > canonical `docs/architecture/*` > `contracts/` > state machines & sequences > data/provider/security/ops/test specs > proposed ADRs/examples.
- `docs/ARC_OVERVIEW.md` is the narrative product/architecture overview (vision, scaling, deployment profiles, tenant model). Read it for the big picture.
- Canonical architecture: `docs/architecture/01_OVERALL_ARCHITECTURE.md`. `docs/architecture/ARCHITECTURE_FULL.md` is **generated by concatenating the numbered `00..25_*` files — edit the numbered files, never the generated one.**
- `governance/DECISION_LEDGER.yaml`: 36 `LOCKED` decisions are binding. Every technology choice (ordered-stream tech, actor runtime, durable workflow, SFU, renderer, STT/TTS/search providers, cloud/region) is `OPEN`/`PROPOSED` and is **not** accepted architecture — prototype only, never present as decided. `docs/adr/proposed/*` are proposals, not accepted decisions.
- `governance/TERMINOLOGY_REGISTRY.yaml` fixes canonical names (`ClassroomActor`, `TeacherOrchestrator`, `TurnManager`, `TimelineController`, `SpeakingFloor`, `SFU`, `CTF`, ...). Do not rename them. `AI_IMPLEMENTATION_GUIDE.md` holds the binding "forbidden" list and definition-of-done.
- `MANIFEST.json`, `FILE_INDEX.md`, `TREE.txt`, and `CONSISTENCY_REPORT.md` are point-in-time snapshots of the spec package (they omit `tasks/` and `backend/` source). Do not treat them as a live index.

## Task workflow (binding, easy to miss)

- Work is driven by `tasks/`, not free-form requests. Pick the single unblocked task from `tasks/STATUS_BOARD.csv`, respecting `tasks/DEPENDENCY_GRAPH.md`. **WIP limit = 1** (`tasks/SOLO_RULES.md`).
- Each task dir has `TASK.md` (scope + acceptance), `PROMPT.md` (agent protocol), and `STATUS.yaml`. When handed a `PROMPT.md`, first return the analysis plan it asks for (requirements + LOCKED decisions, invariants, failure/timeout/retry/recovery paths, exact files, tests, blockers) **before writing code**, then implement only the `TASK.md` scope.
- Rules: do not expand scope; update `contracts/` before changing interfaces; keep domain logic independent of provider SDKs; never replace a mock and change domain behavior in the same task.
- FND-001 ("Repository bootstrap and quality commands") is still `TODO`, so there is **no CI and no ruff/mypy/lint config yet**. Do not assume quality commands exist.

## Commands (backend)

- Install: `cd backend && python3 -m venv .venv && .venv/bin/pip install -e ".[dev]"`
- Run API (dev): `cd backend && env -u PYTHONPATH .venv/bin/uvicorn app.api.app:create_app --factory --reload --port 8001` (Swagger at `/docs`; tenant via `X-Institution-Id` header)
- Test (all): `cd backend && env -u PYTHONPATH .venv/bin/python -m pytest -q`
- Single file / test: append `tests/test_pptx_extractor.py` or `tests/test_pptx_extractor.py::test_table_is_extracted`.
- `pytest` uses `asyncio_mode = "auto"` (`backend/pyproject.toml`), so async tests need no `@pytest.mark.asyncio`.

## Commands (frontend)

- Run both servers at once: `./run.sh` (add `--install` to set up deps first). Frontend on `:8000`, backend on `:8001`; Ctrl+C stops both.
- Frontend runs on **:8000** (Vite dev server); backend API runs on **:8001**. Vite proxies `/courses`, `/artifacts`, `/health` to the backend (`MENTORA_BACKEND_ORIGIN`, default `http://127.0.0.1:8001`), so the browser only talks to `:8000` (no CORS).
- Backend: `cd backend && env -u PYTHONPATH .venv/bin/uvicorn app.api.app:create_app --factory --reload --port 8001`
- Frontend: `cd frontend && npm install && npm run dev`
- Build (optional single-origin mode): `cd frontend && npm run build` → `frontend/dist/`; the backend then also serves that build at `/` when present (override the location with `MENTORA_FRONTEND_DIST`).

## Environment gotcha (important)

This shell has ROS 2 installed and `PYTHONPATH=/opt/ros/jazzy/lib/python3.12/site-packages` set globally, which breaks the venv's `pytest` (ROS plugins load and fail on `ModuleNotFoundError: No module named 'yaml'`). **Always prefix Python/pytest commands with `env -u PYTHONPATH`** when running against `backend/.venv`.

## Core product-logic boundaries (non-obvious)

- The **Teacher Orchestrator** is central product logic; LLM, TTS (OmniVoice), search, and media providers are explicitly *replaceable infrastructure* behind interfaces.
- Deterministic data (attendance, grades, completion, slide numbers, permissions) comes from services/DB, **never from LLM memory**.
- Backend sends semantic presentation events (e.g. `goto_slide`, `highlight`), not raw LLM-generated HTML.
- Keep realtime audio off the general API/message-bus hot path.
- Every installation is scoped by `institution_id`; all authorization checks must enforce that tenant boundary.
- LLM Router should route simple state checks to small/deterministic paths, not the largest model.

## Implemented backend (`backend/app/`)

First V0 slice: secure PPTX upload + SQLite persistence + deterministic structural extraction.

- `security/` — upload validation: size limit, filename normalization, extension + magic-byte checks, stable `ErrorCode`s.
- `storage/` — `ObjectStore` ABC + atomic, content-addressed `LocalObjectStore`.
- `courses/` — course/version/source-artifact/compiler-job models, tenant-scoped `CourseRepository`, `UploadService` (idempotent dedupe by SHA-256 or `Idempotency-Key`).
- `compiler/` — internal Content IR (mirrors `contracts/ctf/scene.schema.json`, `content-ir/1.2.0`) + dependency-free OOXML `.pptx` extractor (stdlib `zipfile` + `xml.etree`, zip-bomb bounds) + `ExtractionService`. V0-018 makes the IR carry the **effective** look: theme scheme colours + font scheme (with `p:clrMap` remapping), slide→layout→master placeholder inheritance and `p:txStyles` defaults, slide/layout/master backgrounds (a **picture** background resolves against the relationships of the part that declares it — a layout's art-directed background belongs to the *layout* — and falls through, with a warning, when its bytes cannot be inlined), shape fill/line/gradient/geometry/rotation/flip, exact run+paragraph formatting (`sz`/`b`/`i`/`u`/spacing/bullets/`lnSpc`), group transforms applied so child bounds are absolute, embedded image media refs + `srcRect` crop, and table metrics/cell styling. It also carries the art a slide **inherits** from its layout and master (`inherited_objects`: non-placeholder chrome, each part resolved against its own rels, `showMasterSp` honoured), so the renderer can paint the deck's shared crest/badge/rules under the slide's own objects. Charts, SmartArt, animation and exotic effects stay flagged placeholders.
- `compiler/renderers/` + `compiler/render_service.py` — provider-neutral `DocumentRenderer`, selected by **mode** (`renderers/factory.py`; **no renderer technology accepted** — `DEC-TECH-005` is `OPEN`), behind the per-slide fidelity gate (V0-005). **`faithful` is the default (V0-019 v5)**: `StructuralSvgRenderer` reproduces the **source deck's own layout and styling** and reports `STRUCTURAL_RENDERED` — backgrounds, gradients, preset + `custGeom` paths, fills/strokes/dashes, rotation/flip, real font sizes with word-wrap + alignment + bullets + auto-shrink, embedded pictures inlined as `data:` URIs with crop, tables, connectors. The product rule is *"same layout as the author's deck; where a component cannot be reproduced, draw it in the platform's default look, in place"*: an **unavailable source font** is substituted with the platform's type stack (`mentora_theme.py`), deterministically so the client's own fonts can never change the asset, and recorded as `FONT_SUBSTITUTED:<family>` (a frame whose font was substituted is shrunk to stay inside the author's frame rather than spilling over its neighbour); a **chart/SmartArt/WordArt/equation/graphic frame** becomes a flat platform panel labelled with the object (`UNSUPPORTED_OBJECT:<kind>`); an **un-inlinable picture** (EMF/WMF/TIFF, over budget, bytes not supplied) becomes a flat platform panel labelled with the part. Each is a **warning**, not a degradation: the content is complete and the layout is the author's, so such a scene stays `STRUCTURAL_RENDERED`, publishable and `requires_review=False`; `DEGRADED_RENDERED` stays reserved for a scene that genuinely cannot be drawn. Because the author's geometry is kept, the author's *overlaps* are kept too. `themed` is the opt-in alternative (V0-019 v4, `mentora-themed-svg@4.0.0`): `ThemedSvgRenderer` **re-lays the content out** — *the grouping is the author's, the content is the author's, the look is the platform's* — reporting `THEMED_RENDERED`, a re-layout rather than a rank on the fidelity-to-source ladder. The extracted objects keep their source boxes, and a binary widest-gap XY-cut (`renderers/flow.py::structure`) recovers the slide's **rows and columns**, so an icon stays beside its label and a card keeps its parts (a column is only cut when both sides are a substantial share of the region, so an icon column never splits from its label); each recovered cell is folded into flow blocks (merged paragraph lists, tables, rows of ≤4 pictures, and a panel for a chart/SmartArt) and placed by a single measuring pass over a cursor (`renderers/textmetrics.py`: measure and place are the same computation, so blocks cannot overlap — `tests/test_flow_layout.py` asserts the invariant pairwise over the emitted geometry). A cell that draws more than one block becomes a **card**: content inset and a flat `theme.surface` rounded panel painted behind it (no border, excluded from the no-overlap geometry). A heading is hoisted (kicker/title/subtitle above one hairline rule) and the page number lives in a reserved bottom strip the flow may not enter. The look is entirely the platform's (`mentora_theme.py`: its type stack, its type scale, its palette; a source size only selects a `lead`/`body`/`caption` row), so no source typeface, colour, fill or geometry is reproduced. Its gate is **content completeness**: nothing is re-selected, re-ordered or dropped — content that cannot be fitted even at the smallest readable scale is still drawn in full, flagged `TEXT_OVERFLOW:<scene>` and degraded for review (the page number is omitted so nothing is covered), and an object it cannot redraw (chart/SmartArt) becomes a labelled panel and degrades with `UNSUPPORTED_OBJECT:<kind>`. `?mode=faithful|themed` selects the mode. Images reach both through `RenderRequest.media` (keyed by IR `media_ref`) — a renderer never opens the source package (`DEC-CONTENT-001`). Self-limiting: a per-scene raw-byte budget (`RenderConfig.max_inline_media_bytes`) turns over-budget or non-inlinable (EMF/WMF/TIFF) pictures into platform panels with a `MEDIA_BUDGET_EXCEEDED:`/`UNSUPPORTED_*` warning **without** changing fidelity, so gate semantics stay stable. The theme is versioned and folded into the renderer config hash, and the package cache key binds the renderer identity (`name@version`: `local-structural-svg@3.1.0`, `mentora-themed-svg@4.0.0`), so one mode's package can never be confused with the other's. Endpoints `POST /artifacts/{id}/compile`, `GET /artifacts/{id}/renders/{order}`, `GET /renderer` (all accept `?mode=`). **V0-019 v7**: a slide draws the art it *inherits* — the deck's shared chrome (crest, badge, rules, static labels) lives on the **layout**/master, is walked as non-placeholder `inherited_objects` (each part resolved against its own rels, `showMasterSp` honoured on the slide and on the layout), and is painted master-first, layout-second, the slide's own objects last. It is not slide content (no reading order of its own, never in the slide's text or `object_count`); on the reference deck it is the top-right logo pair that 26 slides carry only in the layout. `themed` re-authors the look, so it does not carry the chrome and says so in its notice.
- `compiler/package_builder/` + `compiler/validators/package.py` — baseline Content Package builder (V0-006): IR + renders → scene documents, copied content-addressed assets, fallback lesson plan with safe markers, and a checksummed manifest (written last = commit point). Contract: `contracts/ctf/PACKAGE_LAYOUT.md`. **Library/stage only — it has no endpoint of its own; `publication/` serves it read-only.**
- `publication/` — **teacher review** of a built package (V0-007) and the **atomic publication transition** (V0-008). `review.py` is the read-only projection (`POST/GET /artifacts/{id}/review-package` + `/renders/{order}`); `workflow.py`/`repository.py`/`draft.py` are the write path — `POST .../decision` (approve/reject), `GET .../review-state`, and `POST/GET .../drafts` (append-only draft lesson-order revisions stored in `review_decisions`/`review_drafts`, never in the package). Approve sets `CourseVersionStatus.APPROVED`.
- `publication/service.py` + `seal.py` + `index.py` + `outbox.py` — **V0-008 publication**: `POST /course-versions/{id}/publish` seals the built package (re-validate + `manifest_sha256` envelope digest + `content_digest` over the manifest's listed files, sorted), establishes the pinned knowledge-index version (`IndexBuilder` ABC + `BaselineIndexBuilder`, which declares the package's own `knowledge_index_version` — `"unindexed"`, `DEC-TECH-008` is `OPEN`; V0-014 replaces it), then commits in **one transaction** (`repository.py::PublicationRepository.commit`): index-version record + publication row + outbox row + guarded `APPROVED→PUBLISHED` status update + supersede of older versions. `SEALING`/`INDEXING`/`COMMITTING` are **in-process only**, never persisted, so partial publication is invisible by construction and a refusal (409 `PUBLICATION_BLOCKED` with `issue_code` `NOT_APPROVED`/`STALE_APPROVAL`/`WRONG_STATE`/`CHECKSUM_MISMATCH`/`INDEX_FAILED`) writes nothing. Idempotent on `(version_id, content_package_version)` (`DEC-RUNTIME-003`): a replay returns the same publication with `created: false`, a correction is a **new course version**, and the old publication is `SUPERSEDED` (linked via `superseded_by`) — never deleted, so a pinned session keeps reading it (`DEC-CONTENT-005`). Reads: `GET /course-versions/{id}/publication`, `GET /publications/{id}` (superseded included), `GET /courses/{id}/publications`; `?verify=true` re-checks the pinned package against the sealed digest and reports `VERIFIED`/`MISMATCH`/`MISSING`. Tables `publications`/`knowledge_index_versions`/`publication_outbox` (`database/migrations/0003_atomic_publication.sql`); the outbox is written but not dispatched (`DEC-TECH-001` `OPEN`).
- `db/` — SQLite connection handling + `app/db/schema.sql`.
- `api/` — FastAPI app factory (`create_app`) + `spa.py` (`SpaStaticFiles`: the
  single-origin frontend mount answers client-side routes such as
  `/studio/{artifactId}` with the app shell, while still 404ing a missing asset).

Not yet implemented (reserved in the spec only): LLM, voice/OmniVoice, knowledge/RAG, presentation, teacher/orchestrator, session, student, class_management, persistence. See `backend/README.md` for endpoints and design notes.

## Implemented frontend (`frontend/`)

Minimal Vite + React + TypeScript + Tailwind upload UI (the spec's frontend stack), served by the backend at `/`. It sets the `X-Institution-Id` tenant header, lists/creates courses, uploads or drag-and-drops a `.pptx`, and renders the extracted Content IR. **It has two real pages** routed by `src/router.tsx` (a dependency-free `useRoute`/`navigate`/`Link` module — no router dependency): `/` (`src/pages/UploadPage.tsx`, the library above) and `/studio/{artifactId}` (`src/pages/StudioPage.tsx`, the full-width Teacher Studio, built to be opened in its own tab on a large screen; it sets its own document title from `GET /artifacts/{id}` and shares the tenant through `src/institution.ts` + `localStorage`). `src/components/TeacherStudio.tsx` is the V0-007 **Teacher Studio** review component those pages render: side-by-side slide render + extracted text/notes/fidelity, warnings and blocking status, approve/reject (refused server-side for a blocking failure), draft lesson-order/script edits that never touch the package, a **Focus slide** toggle + browser fullscreen for large-screen viewing, and keyboard + screen-reader support. Its component tests (`TeacherStudio.test.tsx`, `StudioPage.test.tsx`, `App.test.tsx`, `router.test.tsx`, vitest + Testing Library, dev-only deps: `npm test`) cover the blocking-warning path, the page's load/build orchestration and the routing. Source under `frontend/src/` (`App.tsx`, `api/client.ts`); `frontend/dist/` is a build artifact and is git-ignored. The rest of the spec's `frontend/src/{audio,classroom,presentation,quiz}/` module layout is for later feature work, not this slice. See `frontend/README.md`.

## Backend persistence note

SQLite is the V0 local/dev equivalent of the durable store required by `DEC-DATA-001` ("PostgreSQL **or equivalent**"). Schema is isolated in `backend/app/db/schema.sql`; the PostgreSQL reference is `database/migrations/0001_baseline.sql`. Keep the repository layer storage-agnostic so PostgreSQL can replace it. Connection handling is `backend/app/db/database.py`: `Database` gives **each thread its own connection** (the API serves sync endpoints from a worker threadpool, and a shared `sqlite3.Connection` lets concurrent requests interleave transactions and cursors — V0-020), with `PRAGMA busy_timeout` so concurrent writers queue. `connect()` still returns a plain connection for single-threaded callers/tests.

## Provider/interface convention

External capabilities (LLM, TTS, search, object storage) are hidden behind `*Provider`/`*Store` ABCs with local dev implementations. Do not add real API keys or network calls without wiring them through an interface and a corresponding task.
